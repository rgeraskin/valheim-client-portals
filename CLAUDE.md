# CLAUDE.md

ClientPortals: a client-side Valheim mod (BepInEx 5, C# targeting net462, no Jötunn) to pick a portal destination from a list or on the map, with full gamepad support. User docs: README.md.

## Commands

Tools come from mise (`mise.toml`: dotnet 10). `VALHEIM_DIR` defaults to `.deps/` (a copy of the Windows game's `valheim_Data/Managed` and `BepInEx/core`, made by `tools/fetch-local-deps.sh`; the macOS Steam build is a different game build).

- `mise run build` — Release build of `ClientPortals/ClientPortals.csproj`
- `mise run test` — xunit tests (`ClientPortals.Tests`, net10.0): atlas merge/removal/serialization, destination list, selection/scroll, translations, Harmony patch targets
- `mise run package` — `dist/ClientPortals-<version>.zip` (fails if `package/manifest.json` and `Plugin.Version` disagree)
- `uv run tools/make_images.py <shots dir> <Cinzel.ttf>` — `package/icon.png`, `logo.png`, `nexus-header.jpg`, `gallery/*.jpg` from harness screenshots (title in Cinzel, OFL; shots of another shape, like a Mac window's 2880x1558, are cut to 16:9 around the center and scaled to 1920x1080)

## Architecture

- `Atlas` (pure): known portals keyed by `PortalPos` (position in decimeters; ZDOIDs change every world load). Entries carry a game-time stamp; merges keep the newer copy; removals are kept as markers so they spread through tables (pruned after 60 days).
- `Destinations` (pure): filtering/sorting of the list (tabs All/Favorites/Ignored, name/nearest/farthest, hide nearby, `HideTwins`: of same-name portals keep the farthest from the source), display names, selection/scroll helpers. Names compare through `Fold` (lower case, ё→е): Mono's `OrdinalIgnoreCase` folds only ASCII. Unit-tested.
- `Journal`: the local player's atlas + favorites + ignored portals per world in `Player.m_customData` (`ClientPortals.Atlas.<worldUID>`, `ClientPortals.Favorites.<worldUID>`, `ClientPortals.Ignored.<worldUID>`, `ClientPortals.IgnoreUnnamed.<worldUID>` = every unnamed portal ignored; the last view in `ClientPortals.LastView`).
- `Learner`: once a second, learns portals within `NearbyDistance` (all of them on a host with `HostKnowsAll`), the other end of tag pairs (requesting the ZDO), and forgets known portals missing from a loaded area for 5 s.
- `Travel`: the game's rules (`Allowed`), fetches the live portal ZDO when its session id is known, teleports like vanilla, verifies the portal on arrival, and blocks walk-in/tag teleports for 2.5 s after arriving.
- `PortalPatches`: hover hint (gamepad glyphs written `[<color=yellow><b><sprite…></b></color>]`: the HUD drops those brackets), `LongerPortalNames` (the game's tag dialog at a portal gets `NameLimit`), `TravelKey` (Q / a tap on gamepad L3 at the hovered portal opens `Picker`: L3 opens it when let go without JoyUse meanwhile, as L3 is also the game's JoyAltKeys and L3 + A renames a pair; while held at a portal `PlayerController.TakeInput` is false, so Q's auto-run and L3's crouch/run don't fire), alt-use renames a pair (`PairRename`), walk-in, `ShowActive` glow; `TextInput.IsVisible` is patched to block game input while the list is open (the game checks it everywhere), and `HotkeyBar.Update` (it reads the D-pad without checking dialogs).
- `TablePatches`: atlas on the map table ZDO (`ClientPortals.Atlas`), merged on read/write, count in the hover text.
- UI is uGUI built from the game's own pieces (`Ui`): the tag dialog's panel/title/input field (`TextInput`), the crafting list's row prefab, tabs, craft button and scrollbar (`InventoryGui`), cloned with `Ui.Clone` (strips `UIGamePad` hotkeys and navigation, resets click events). Windows live under the game's GUI root canvas. Gamepad glyphs come from `Localization.GetBoundKeyString("Joy…")` (TMP sprite tags).
- `ListWindow` (mouse/keyboard/gamepad via `ZInput` button names, see `Pad`) and `MapPicker` (badges under `Minimap.m_pinRootLarge` placed with the map's own `MapPointToLocalGuiPos`; hint bar and hover label in `m_largeRoot`; gamepad uses the screen center like the game's crosshair). Tab / the View button switches between them, the search going along (in the map view also the map key: a `Minimap.SetMapMode` prefix notices it closing the map); `View` picks the view a portal opens (`Last` = `Journal.LastViewMap`). The map view's search box (also there with a gamepad, for a touch on a streaming device) filters the badges and zooms them into the part of the map no panel covers (`FreeArea`); while the view is open with keyboard/mouse `MapPicker.BlocksInput` makes `TextInput.IsVisible` true, so the map key, Esc and movement don't reach the game. Map → list opens the All tab.
- Labels keep one font size through text changes with `Ui.SetLabel(control, text, all)` / `Ui.SetLabels` (the game's buttons auto-size each text).
- `PairRename` (opt-in `RenameBoth`): `RenameKey` (Shift + E; the game's alt-use is swallowed while that key is held) or the gamepad's alt + use on a paired portal opens the game's text dialog with its own `TextReceiver`; the portal is renamed through the game's RPC and the other end's ZDO (requested if not loaded) gets the same `s_tag`/`s_tagauthor`, so the server's `ConnectPortals` pairs them again. `OpenFor` renames a list entry (… mark / F2) the same way, its object fetched by session id; the list hides behind the dialog (`renaming`) and comes back.
- `PortalLabels` (opt-in `Labels.Enabled`): a `PortalLabel` TextMesh (with 4 outline copies) on every `TeleportWorld` (`Awake` postfix), billboarded, hidden past `MaxDistance` or behind solids (raycast). Same settings as Teleporter Overhead Text.
- `Compat`: TagConnectedPortals (`neobotics.valheim_mod.tagconnectedportals`) or Teleporter Overhead Text (`ModdedWolf.Teleporter_Overhead_Text`) installed turns the matching feature off; logged in `Plugin.Start`. Zen.ModLib (`ZenDragon.Zen.ModLib`) moves the game's alt-use to its "Alternate Interact Key" (Q by default, like `TravelKey`) and rewrites hover hints matching `[<color=yellow><b>Shift + E</b></color>]` to it: the mod's keyboard hints use `[<b><color=yellow>…</color></b>]` (not matched), and `TeleportWorld.Interact` is swallowed while the travel or rename key is held (logged when the keys are the same).
- Keyboard: `ListWindow`/`MapPicker` give the search box the keyboard only once the keys that opened them are up (`Ui.AnyKeyHeld`: a held W walking in typed wwww), and keep the caret at the end for a few frames (`stringPosition`; `MoveTextEnd` counts stale drawn characters). Letters typed on the list or the map (after a click took the keyboard from the box) come from `Keyboard.onTextInput` and go on in the search box. While the list or the map view (keyboard/mouse) is open: `Input.GetKey*` (legacy) returns false for keyboard keys (other mods' hotkeys), and the game takes no keys (`TextInput.IsVisible`), so `MapPicker` handles Tab/Esc/wheel zoom itself. Under the list the game's wheel reads 0 (`ZInput.Internal_GetMouseScrollWheel`; the list scrolls from `Mouse.current.scroll`), F2 doesn't toggle the network panel (`ConnectPanel.Update`). `OnlyPortals` turns the map's `m_visibleIconTypes` off (saved, restored on close). Its switch and `ShowNames`' are clones of the map's "visible to other players" switch on the right of the bar's top row (`LayoutToggles`; not in the map's corner, where other mods such as Tunnelheim add theirs); gamepad X / L3. Names (`PlaceNames`, `namesRoot` under the badges) use the map's pin name prefab, favorites then nearest first, and stay off where they would overlap a name, a badge or the bar, or leave the map. The hover label (`PlaceLabel`) goes below a badge where the bar would cover it. The bar is the same with a gamepad (search box, button, switches laid out for the gamepad labels either way). Esc (and B: the `SetMapMode` prefix keeps the map open) empties the search first, like Esc/B in the list; list rows lose their mouse hover tint under the gamepad (`HoverLook`). `Ui.Panel(mirrorBottom)` builds the dialog panel from its upper half twice (the lower flipped): the sprite's bottom edge is torn.
- `Texts`: every UI string × the game's 35 languages (positional rows, one text per `Keys` entry); `Texts.T(key, words)` reads the row of the `Language` setting, or the game's language on `Auto`. Tests check rows are complete, `$1` kept, and every `T("…")` key exists.

## Testing in game

`tools/DevHarness` is a dev-only plugin (never shipped; reads the plugin's internals through a publicized reference) that loads a local world with a test character and runs commands written to `<harness dir>/cmd.txt`, logging to `log.txt` and saving `shots/*.png`. Input goes through a virtual gamepad and the keyboard device (Unity Input System), so the game and the mod read it like a player's. Tests run on a Windows machine over SSH (`CLIENTPORTALS_REMOTE=user@host` in the untracked `mise.local.toml`), in an isolated BepInEx profile `D:\ClientPortalsTest` started by the scheduled tasks `ClientPortalsTest` (world from `run.cmd`) and `ClientPortalsShowcase` (`run-showcase.cmd`: the world `PortalShowcase` with named portals for the mod page); the user's mod-manager profiles are never touched. Scripts in `tools/harness/`: `remote-redeploy.sh` (quit, copy DLLs, start; `CLIENTPORTALS_TASK` picks the task), `remote-cmd.sh` (commands on stdin, prints the new log lines), `remote-ps.sh`. The same harness runs on a Mac with the Steam game: `tools/harness/local-game.sh` (BepInEx under Rosetta in the isolated profile `.harness/profile`, the game folder's own plugins untouched; world `CLIENTPORTALS_WORLD`, default `PortalShowcase`, copied from the Windows machine's `worlds_local`; window `CLIENTPORTALS_SCREEN_W`/`_H`, default 1280x720: 1920x1080 for gallery shots) and `local-cmd.sh`; it refuses while any Valheim runs there. The harness's `type` text events reach `Keyboard.onTextInput` but not a focused TMP input field (it reads the OS's key events): only the first letter typed on a list/map lands in the box.

Commands: `waitplayer`, `god`, `wait <s>`, `frames <n>`, `settle [s]`, `portals [n]`, `tpname <tag> [nth]`, `tpportal <i>`, `tpoffset <right> <forward>`, `tp <x> <z>`, `open` (the nearest portal's picker), `altuse` (Shift + E at the nearest portal), `walkin`, `hover`, `pad <a|b|x|y|lb|rb|lt|rt|up|down|left|right|select|start>[+...] [frames]`, `stick <x> <y> [s]`, `key <Key>[+Key]`, `search <text>`, `click <button|toggle>`, `mouseat [tag]`, `mapclick`, `maprightclick`, `mousepark`, `state`, `journal [n]`, `mapinfo`, `title`, `ui` (layout dump), `shot <name>`, `camshot <name> <yaw> <pitch> <dist> <height>`, `hud on|off`, `hideplayer on|off`, `aim <right> <up>`, `time <0..1>`, `env <name>`, `lang <Language>|restore`, `cfg <key> <value>`, `forget`, `give <item> [n]`, `mapsearch <text>`, `textinput`, `textenter <text>`, `keydown <Key>` / `keyup` (held keys), `type <text>` (keyboard text events), `scroll <y>` (wheel; logs camera distance and map zoom), `mapmiddleclick`, `names` (which badges show their name), `pointat <name>` (the game's mouse on a badge without moving the system cursor; `mouseat` moves it), `pointxy <x> <y>`, `focus` (search focus, caret, legacy key patch, pins shown, network panel), `favorite <tag>`, `table`, `tablewrite`, `tableread`, `placeportal <prefab> <x> <z> <yaw> <tag>` (on the solid ground where loaded: a floating portal breaks), `clearnature <radius>`, `keyprobe <Key> <KeyCode>` (what each input layer and the travel key see), `ray` (the hover ray's hits), `findbiome <Biome> [min] [max]`, `exploreall`, `save` (the world and the character, so a restart loads them: the cartography table test writes, saves, restarts, `forget`s and reads), `quit`. Wait for `settle` after any travel before the next teleport, and a few seconds after spawning before screenshots (the UI fades in). This harness waits in game time: never send Esc with nothing open (the pause menu stops game time, and with it the harness; only a restart helps). The game's hover needs the camera on a portal's frame within 3.5 m: `aim` (repeat it, the camera eases) then `ray`. `remote-redeploy.sh` refuses (exit 3) while a Valheim not started from this profile runs. `run.cmd` plays the world `PortalTest`, `run-showcase.cmd` `PortalShowcase` (the gallery scene: a portal room at (60, 0) paired with far portals in other biomes).

## CI and releases

- `.github/workflows/ci.yml` (push to master, PRs): `tools/ci/fetch-deps.sh` (the dedicated server's Managed assemblies via anonymous steamcmd + BepInExPack from Thunderstore; versions in `tools/ci/versions.env`, cached weekly), build, tests, package (artifact `package`). Build like CI locally: `tools/ci/fetch-deps.sh <dir>` then `-p:ValheimDir=<dir>`.
- `.github/workflows/release.yml`: a tag `v<version>` makes a GitHub release with the zip and publishes with `tools/release/publish.cs` (adapted from Winter Sled's) to Thunderstore and Hexium (categories in `tools/release/sites.json`: always `client-side` / `Client-only`); Nexus Mods (mod 4751, file group 8291019: the `file-group-id` on the mod's Files tab, which the v3 API calls a mod file) was skipped until its first file was uploaded by hand (in the layout publish.cs uploads: `BepInEx/plugins/ClientPortals/` with the dll, README and CHANGELOG) and `modId`/`modFileId` are filled in; every release also sends `package/nexus-description.bbcode` (the Nexus page text, BBCode: keep it in step with README.md) and the manifest's description as the page summary. Run by hand it is a dry run. Secrets: `THUNDERSTORE_TOKEN`, `HEXIUM_TOKEN`, `NEXUS_API_KEY`.
- To release: version in `package/manifest.json` and `Plugin.Version`, a `## <version>` section in CHANGELOG.md, commit, `git tag v<version> && git push --tags`.
- Lint workflows: `mise x aqua:rhysd/actionlint@1.7.12 -- actionlint`
